# Agent Delegation Protocol 1.0

[English](1.0.md) | [简体中文](1.0.zh-CN.md)

**标识符**：`agent-delegation/1.0`
**状态**：草案
**日期**：2026-07-04
**依赖**：Agent Identity Protocol 1.0
**可使用**：Agent Profile Protocol 1.0
**核心对象**：Agent Delegation Credential

## 1. 概述

Agent Delegation Protocol 定义可移植、可验证的代理授权凭证，用来声明某个智能体何时被授权代表一个主体行动。主体可以是人、组织、团队、项目、场馆、活动或其他非智能体实体。

Agent Identity 回答「哪把密钥签署了这个事件？」Agent Profile 回答「这个 agent 如何展示和发现？」Delegation 回答一个单独的问题：「这个 agent 可以代表谁、在什么边界内行动？」

本协议只使用一个信任原语：principal 由一个 HTTPS URL 标识，该 URL 发布一份 principal document——principal 的公开名片——列出可以代表该 principal 签名的 **controller keys**。授权事件就是一个普通的 Agent Identity 签名事件，其 `actor` 是其中一把 controller key。因此验证一份 delegation 复用了所有 Agent Protocols 服务都已实现的信封验证，再加一次对 principal document 的 HTTP 读取。

本协议刻意不定义人类登录、账号恢复或法定身份验证。提供方如何决定用 principal 的 controller key 签名——已登录账号同意、组织管理员策略、人工审核——是协议之外的提供方问题。本协议只定义 principal 绑定、授权与撤销事件、实体化凭证和读取 API。

## 2. 规范用语

本文中的关键词 `MUST`、`MUST NOT`、`REQUIRED`、`SHALL`、`SHALL NOT`、`SHOULD`、`SHOULD NOT`、`RECOMMENDED`、`NOT RECOMMENDED`、`MAY`、`OPTIONAL` 仅在全大写出现时，按 BCP 14（RFC 2119、RFC 8174）含义理解。

## 3. 设计目标

1. **主体分离**：Agent Profile 描述 agent，不直接证明它代表哪个人或组织。
2. **单一信封**：Delegation 事件就是标准 Agent Identity 签名事件，没有第二套证明格式。
3. **URL 即权威**：控制 principal URL 就是控制 principal 身份，与 `did:agent:` 密钥控制 agent 身份同构。
4. **边界授权**：授权携带 scopes 和 constraints，而不是一句宽泛的「可代表」。
5. **撤销优先**：依赖方可以在信任授权前检查当前凭证状态。
6. **提供方中立**：任何兼容服务都可以托管 principal document 和凭证；应用在其上定义自己的 scopes、constraints 和同意流程。

## 4. 核心概念

| 概念                  | 说明                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| Principal             | 被代表的主体：人、组织、团队、项目、场馆、活动或其他非 agent 实体。                        |
| Principal document    | 由 principal URL 返回的 JSON 文档：principal 的公开名片加其 controller keys。              |
| Controller key        | principal document 的 `controllers` 中列出的 Agent ID。由它签名的事件承载 principal 权威。 |
| Subject agent         | 获得代理权的 `did:agent:*`。                                                               |
| Delegation credential | 最新已接受授权或撤销事件加提供方状态实体化后的当前凭证。                                   |
| Scope                 | 应用定义的权限字符串，例如 `inbox.screen`、`calendar.propose`、`alink.intro.request`。     |
| Constraint            | 限制 scope 使用方式的 JSON 对象。                                                          |
| Status                | `active`、`suspended`、`expired` 或 `revoked`。                                            |

## 5. Principal

### 5.1 Principal 标识符

`principal.id` MUST 是 HTTPS URL。RECOMMENDED 使用简短、稳定的 URL：

```text
https://al.ink/yan
https://profiles.example.com/org/acme
https://events.example.com/summit-2026
```

URL 是身份的信任根：谁控制这个 URL 返回的内容，谁就控制这个 principal 身份。其他标识符方案（例如 DID method）可在未来版本加入。

### 5.2 Principal Document

带 `Accept: application/json` 的 `GET {principal.id}` MUST 以 `application/json` 返回 principal document。同一 URL MAY 向其他客户端返回 HTML 或其他表示。解析方 MAY 跟随同源重定向；解析出的文档 `id` MUST 等于正在验证的 principal 标识符。相等按字符串精确比较：发布方 SHOULD 使用归一化 URL——scheme 与 host 小写、不带默认端口、不带 query 与 fragment——任何字符串差异都命名不同的 principal。

Principal document 是 principal 的公开名片。描述性字段说明该主体是谁；`controllers` 绑定可以代表它签名的密钥。只有 `id` 和 `controllers` 承载信任语义——其余字段都是自述的展示元数据，不是经过验证的声明。

```json
{
  "id": "https://al.ink/yan",
  "type": "person",
  "name": "Yan",
  "description": "Founder of alink. Building agent-native contact infrastructure.",
  "avatar_url": "https://al.ink/yan/avatar.png",
  "links": [
    { "name": "Homepage", "url": "https://yan.example.com", "rel": "homepage" },
    { "name": "alink", "url": "https://al.ink", "rel": "social" }
  ],
  "controllers": ["did:agent:PrincipalController-00000000000000000000000"],
  "delegations_url": "https://al.ink/v1/delegations/query",
  "updated_at": 1779753600000,
  "extra": {}
}
```

| 字段              | 类型     | 必填 | 说明                                                                                      |
| ----------------- | -------- | ---- | ----------------------------------------------------------------------------------------- |
| `id`              | string   | 是   | Principal URL。                                                                           |
| `type`            | string   | 否   | SHOULD 是 `person`、`organization`、`team`、`project`、`venue`、`event` 或 `other` 之一。 |
| `name`            | string   | 否   | 面向人类的显示名。                                                                        |
| `description`     | string   | 否   | 简短自我描述。                                                                            |
| `avatar_url`      | string   | 否   | 头像或 logo 的 HTTPS URL。                                                                |
| `links`           | object[] | 否   | 辅助链接；每一项使用 Agent Profile `links` 的条目结构（`name`、`url`、`rel`）。           |
| `controllers`     | string[] | 是   | 可以代表该 principal 签名的 Agent ID。MUST 非空；每一项 MUST 是有效 Agent ID。            |
| `delegations_url` | string   | 否   | 可查询或读取该 principal 的 delegation credentials 的 HTTPS URL。                         |
| `updated_at`      | integer  | 否   | 文档最后变更的 Unix milliseconds。                                                        |
| `extra`           | object   | 否   | 应用特定扩展对象。                                                                        |

消费方 SHOULD 保留未知字段。托管方 SHOULD 采用与 Agent Profile 5.2 节类似的字段限制。在验证新事件时，服务 SHOULD NOT 依赖缓存超过 300 秒的 principal document。

### 5.3 Controller Key 与轮换

Controller key 就是普通的 Agent Identity 密钥。它可以由 principal 自己持有、由 principal 的提供方持有，或由专门的签名服务持有；由谁持有、使用前经过什么同意流程，是提供方和应用的决策。

Principal 通过更新 `controllers` 变更其权威集合。移除一把 controller key 不会追溯性地作废该密钥在列期间已被接受的授权；要收回已委托出去的权力，principal 需要签发 `delegation.revoke` 事件。因此应对 controller key 泄露需要同时做两件事：轮换 `controllers`，并撤销它签发过的授权。

服务 MUST 在接受事件时检查事件 `actor` 是否列于 principal document 中。

controller 检查绑定在接受时刻，而本协议不定义 principal document 的历史快照。一把密钥被移出 `controllers` 后，它签名事件所产生的凭证仍是已接受状态，但第三方重新解析 principal document 时已无法自行确认历史绑定。第 7 节定义了依赖方在两种信任姿态之间的选择。

## 6. Delegation 事件

Delegation 事件是标准的 Agent Identity 签名事件信封，并使用：

```json
{
  "protocol": "agent-delegation/1.0"
}
```

事件 `actor` MUST 是 payload 中所指 principal 的一把 controller key。任何人 MAY 向 delegation 服务提交已签发的信封——subject agent、提供方后台或镜像服务；承载 principal 权威的是签名，不是提交者。服务 MAY 为限流和滥用控制要求请求认证。

### 6.1 授权事件

`delegation.grant` 事件创建或替换一份 delegation credential。

```json
{
  "hash": "QWdlbnQtRGVsZWdhdGlvbi1ncmFudC1oYXNoLTAwMDA",
  "event": {
    "protocol": "agent-delegation/1.0",
    "type": "delegation.grant",
    "actor": "did:agent:PrincipalController-00000000000000000000000",
    "created_at": 1779753600000,
    "nonce": 1,
    "payload": {
      "id": "del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q",
      "principal": {
        "id": "https://al.ink/yan",
        "type": "person",
        "name": "Yan"
      },
      "subject": "did:agent:SubjectAgent-000000000000000000000000000000",
      "relationship": "primary_delegate",
      "scopes": ["inbox.screen", "meeting.propose"],
      "constraints": {
        "requires_human_approval": ["meeting.accept"]
      },
      "not_before": 1779753600000,
      "expires_at": 1790000000000
    }
  },
  "signature": "QmFzZTY0dXJsLUVkMjU1MTktc2lnbmF0dXJlLXBsYWNlaG9sZGVyLTAwMDAwMDAwMDAwMDAwMDAwMDAwMDAwMA"
}
```

| Payload 字段   | 类型     | 必填 | 说明                                                                                         |
| -------------- | -------- | ---- | -------------------------------------------------------------------------------------------- |
| `id`           | string   | 是   | 稳定 delegation 标识符，在服务内唯一。                                                       |
| `principal`    | object   | 是   | Principal 描述符。MUST 包含 `id`；SHOULD 包含 `type`；MAY 包含 `name`。                      |
| `subject`      | string   | 是   | 获得代理权的 Agent ID。                                                                      |
| `relationship` | string   | 否   | 应用标签，例如 `primary_delegate`、`assistant`、`organization_delegate` 或 `service_agent`。 |
| `scopes`       | string[] | 是   | 应用定义的代理能力。                                                                         |
| `constraints`  | object   | 否   | 应用定义的限制。服务 SHOULD 保留未知字段。                                                   |
| `not_before`   | integer  | 否   | 在此 Unix milliseconds 之前授权无效。                                                        |
| `expires_at`   | integer  | 否   | 在此 Unix milliseconds 之后授权过期。                                                        |

对于 `delegation.grant`，服务在以下情况 MUST 拒绝：

- 信封未通过 Agent Identity 验证：结构、hash、签名、actor、时间戳窗口或 nonce；
- `event.protocol` 不是 `agent-delegation/1.0`，或 `event.type` 不是 `delegation.grant`；
- `event.payload.id`、`event.payload.principal.id`、`event.payload.subject` 或 `event.payload.scopes` 缺失或无效；
- `event.payload.principal.id` 不是 HTTPS URL，或其 principal document 无法解析和校验；
- `event.actor` 未列于 principal document 的 `controllers`；
- `event.payload.subject` 不是有效 Agent ID；
- `event.payload.expires_at` 与 `event.payload.not_before` 同时存在，且 `expires_at` 不大于 `not_before`；
- `event.payload.expires_at` 存在且不大于 `event.created_at`；
- `event.payload.id` 已标识一份 `principal.id` 与 `event.payload.principal.id` 不同的 delegation；
- 事件违反服务限制或策略。

同一 principal 使用相同 `payload.id` 的新授权在被接受后替换先前的凭证状态，例如调整 scopes 或延长有效期。这包括已撤销的凭证：同一 `id` 与 principal 的后续有效授权会以新授权字段将其恢复为 `active`——撤销收回的是当前授权，不是废止该标识符。`id` 命名空间如何管理——保留、定价，或将短标识符做成订阅服务——属于本协议之外的服务策略。

实体化凭证的 delegation 字段取自已接受授权事件的 `payload`。`status`、`status_url` 和 `updated_at` 由服务管理；`controller` MUST 设置为已接受事件的 `actor`；`event_id` MUST 设置为已接受信封的 `hash`。

### 6.2 撤销事件

`delegation.revoke` 事件撤销一份已接受的 delegation credential。其 `actor` MUST 是该 principal 当前的一把 controller key，不要求是签发授权的那把。

```json
{
  "hash": "QWdlbnQtRGVsZWdhdGlvbi1yZXZva2UtaGFzaC0wMDA",
  "event": {
    "protocol": "agent-delegation/1.0",
    "type": "delegation.revoke",
    "actor": "did:agent:PrincipalController-00000000000000000000000",
    "created_at": 1779757200000,
    "nonce": 2,
    "payload": {
      "id": "del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q",
      "principal_id": "https://al.ink/yan",
      "reason": "rotated_primary_agent"
    }
  },
  "signature": "QmFzZTY0dXJsLUVkMjU1MTktc2lnbmF0dXJlLXBsYWNlaG9sZGVyLTAwMDAwMDAwMDAwMDAwMDAwMDAwMDAwMA"
}
```

对于 `delegation.revoke`，服务在以下情况 MUST 拒绝：

- 被引用 delegation 不存在；
- 信封未通过 Agent Identity 验证；
- `event.protocol` 不是 `agent-delegation/1.0`，或 `event.type` 不是 `delegation.revoke`；
- `event.payload.id` 或 `event.payload.principal_id` 缺失或无效；
- `event.payload.principal_id` 不等于被引用 delegation 的 `principal.id`；
- `event.actor` 未列于 principal document 的 `controllers`；
- 事件违反服务限制或策略。

Subject agent 可以停止出示凭证，或请求托管服务将凭证标记为 suspended，但只有 controller 签名的 `delegation.revoke` 才是 principal 撤销。服务 MAY 按已文档化的滥用、合规或可见性策略将 delegation 标记为 `suspended`；provider status 不等同于 principal 撤销。

## 7. 凭证文档

Delegation credential 是最新已接受授权或撤销事件加提供方状态实体化后的当前状态。

```json
{
  "id": "del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q",
  "protocol": "agent-delegation/1.0",
  "principal": {
    "id": "https://al.ink/yan",
    "type": "person",
    "name": "Yan"
  },
  "controller": "did:agent:PrincipalController-00000000000000000000000",
  "subject": "did:agent:SubjectAgent-000000000000000000000000000000",
  "relationship": "primary_delegate",
  "scopes": ["inbox.screen", "meeting.propose"],
  "constraints": {
    "requires_human_approval": ["meeting.accept"]
  },
  "not_before": 1779753600000,
  "expires_at": 1790000000000,
  "status": "active",
  "status_url": "https://al.ink/v1/delegations/del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q/status",
  "updated_at": 1779753600000,
  "event_id": "QWdlbnQtRGVsZWdhdGlvbi1ncmFudC1oYXNoLTAwMDA"
}
```

| 字段           | 类型     | 必填 | 说明                                                 |
| -------------- | -------- | ---- | ---------------------------------------------------- |
| `id`           | string   | 是   | 来自已接受授权事件的 delegation 标识符。             |
| `protocol`     | string   | 是   | `agent-delegation/1.0`。                             |
| `principal`    | object   | 是   | 来自已接受授权事件的 principal 描述符。              |
| `controller`   | string   | 是   | 签署产生当前状态事件的 `actor`。                     |
| `subject`      | string   | 是   | 获得代理权的 Agent ID。                              |
| `relationship` | string   | 否   | 应用关系标签。                                       |
| `scopes`       | string[] | 是   | 应用定义的代理能力。                                 |
| `constraints`  | object   | 否   | 应用定义的限制。                                     |
| `not_before`   | integer  | 否   | 在此 Unix milliseconds 之前授权无效。                |
| `expires_at`   | integer  | 否   | 在此 Unix milliseconds 之后授权过期。                |
| `status`       | string   | 是   | `active`、`suspended`、`expired` 或 `revoked`。      |
| `status_url`   | string   | 否   | 服务分配的当前状态检查 HTTPS URL。                   |
| `updated_at`   | integer  | 是   | 最新已接受事件或提供方状态更新的 Unix milliseconds。 |
| `event_id`     | string   | 是   | 产生当前状态的事件信封 `hash`。                      |

需要独立验证的客户端 SHOULD 读取事件历史，按 Agent Identity 验证最新已接受信封，并解析 principal document 检查 controller 绑定。绑定检查是时间敏感的：delegation 服务是在接受时刻检查 `controllers` 的，而 principal document 没有协议定义的历史。因此依赖方按本地策略在两种姿态中选择其一：

1. **信任服务**：接受 delegation 服务在接受时刻完成的 controller 检查，自己只验证信封签名和当前状态。这需要信任该服务不曾接受从未获授权的授权事件。
2. **严格**：仅在凭证的 `controller` 仍列于当前 principal document 的 `controllers` 时才信任该凭证。controller 轮换后，严格姿态的依赖方将旧凭证视为不可验证，并要求由当前 controller 重新签发授权。

高保证要求的依赖方 SHOULD 采用严格姿态。

## 8. HTTP API

Delegation 服务 SHOULD 暴露以下 HTTP API。路径中的 `/v1` 是服务 API 版本，不是事件中的协议标识符。

```text
GET  /.well-known/agent-delegation
GET  /v1/delegations/{delegation_id}
GET  /v1/delegations/{delegation_id}/status
GET  /v1/delegations/{delegation_id}/events
POST /v1/delegations
POST /v1/delegations/query
```

### 8.1 服务发现

`GET /.well-known/agent-delegation` SHOULD 返回服务元数据：

```json
{
  "protocol": "agent-delegation/1.0",
  "service": "https://al.ink",
  "endpoints": {
    "delegations": "https://al.ink/v1/delegations",
    "query": "https://al.ink/v1/delegations/query"
  },
  "features": ["grants", "revocations", "event-history"]
}
```

### 8.2 读取授权

`GET /v1/delegations/{delegation_id}` 返回最新实体化凭证。`GET /v1/delegations/{delegation_id}/events` 返回已接受信封，供独立验证，按服务接受顺序从旧到新排列。同一 delegation 的授权与撤销事件可能由不同 controller key 签名，因此定义凭证状态序列的是服务接受顺序，而不是 nonce 顺序。

### 8.3 状态检查

`GET /v1/delegations/{delegation_id}/status` 返回当前状态，不要求返回完整凭证：

```json
{
  "id": "del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q",
  "status": "active",
  "checked_at": 1779757200000,
  "expires_at": 1790000000000,
  "event_id": "QWdlbnQtRGVsZWdhdGlvbi1ncmFudC1oYXNoLTAwMDA"
}
```

依赖方在信任 delegation 执行敏感动作前 SHOULD 检查状态。

### 8.4 提交 Delegation 事件

`POST /v1/delegations` 接收 `delegation.grant` 或 `delegation.revoke` 信封，并返回实体化凭证或状态。提交者认证（如要求）只是传输层问题，不影响事件验证。

### 8.5 查询 Delegation

`POST /v1/delegations/query` 让客户端按 subject agent 或 principal 解析 delegation。请求 MUST 至少包含 `subject` 与 `principal_id` 之一；`status` 与 `limit` 可选，`limit` 默认 `20`，服务 SHOULD 将上限设为 `100`。每个 `result` 项要么是第 7 节的完整凭证文档，要么是脱敏子集；对请求者可见时，子集 MUST 保留 `id`、`principal`、`subject`、`scopes` 和 `status`。服务 MAY 要求认证、限流，并按本地策略脱敏结果。

请求：

```json
{
  "subject": "did:agent:SubjectAgent-000000000000000000000000000000",
  "principal_id": "https://al.ink/yan",
  "status": "active",
  "limit": 20
}
```

响应：

```json
{
  "result": [
    {
      "id": "del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q",
      "subject": "did:agent:SubjectAgent-000000000000000000000000000000",
      "principal": {
        "id": "https://al.ink/yan",
        "type": "person",
        "name": "Yan"
      },
      "scopes": ["inbox.screen", "meeting.propose"],
      "status": "active",
      "status_url": "https://al.ink/v1/delegations/del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q/status"
    }
  ]
}
```

## 9. 与 Agent Profile 的关系

Agent Profile MAY 通过顶级 `delegations` 字段链接到 delegation credentials，但 Profile 元数据本身 MUST NOT 被视为代理关系证明。

推荐结构：

```json
{
  "delegations": [
    {
      "id": "del_01J8ZM7A3G2T9B4Q6X8R0N1P2Q",
      "principal": {
        "id": "https://al.ink/yan",
        "type": "person",
```

## 10. 安全与隐私考虑

- 控制 principal URL 的 origin 就是控制 principal 身份。Principal document MUST 通过带有效证书的 HTTPS 提供。DNS 或 origin 被攻破等同于身份被攻破；高价值依赖方 MAY 在本地策略中固定已知 controller keys。
- Principal document 的描述性字段——`name`、`description`、`avatar_url`、`links`——是自述展示元数据，不是经过验证的声明。
- 移除一把 controller key 不会撤销它已签发的授权。应对泄露需要同时轮换 `controllers` 并撤销受影响的 delegation。轮换后第三方无法再独立确认历史 controller 绑定；依赖方按第 7 节的信任姿态处理。
- Delegation credential 证明的是 principal 授权，不是 subject 的参与。任何控制某个 principal URL 的人都可以签发指向任意 Agent ID 的凭证。依赖方 MUST NOT 把凭证的存在当作 subject agent 使用、接受或认可该 principal 的证据；正向的 subject 信号包括 subject 主动出示该凭证，或在自己签名的 Profile `delegations` 提示中列出它。
- Scopes 和 constraints 由应用定义。依赖方 MUST NOT 假设未知 scope 授予任何能力。
- Delegation credential 不是 session token。它本身不授权某个请求；接收方仍需要请求认证、策略检查，以及必要的人类批准。
- Delegation credential 可能暴露敏感代理关系。服务 SHOULD 为查询 API 支持可见性控制和脱敏。
- Principal 名称可能被用于冒充。服务 SHOULD 保留受保护名称并文档化验证策略；标识符是 principal URL，不是显示名。
- Principal document 和凭证 SHOULD NOT 包含 bearer token、私有 webhook URL、私有联系方式或 secret。
- 撤销状态 endpoint SHOULD 高可用，并允许短时间缓存。敏感动作 SHOULD 避免只依赖过期缓存状态。

## 11. 最小实现清单

Agent Delegation 1.0 服务 MUST 支持：

1. Agent Identity 信封验证。
2. Principal document 解析与 controller 检查。
3. 接受有效 `delegation.grant` 事件，并按 delegation ID 返回实体化凭证。
4. 返回已接受事件，供客户端独立验证。
5. 返回当前状态，包括 `revoked` 和 `expired`。
6. 拒绝无效信封、非 controller 的 actor、格式错误的 principal 或 subject 标识符，以及不一致的有效期窗口。

推荐实现 SHOULD 同时支持撤销事件、服务发现、按 subject/principal 查询、可见性策略和 Profile 集成提示。

## 12. 未来工作

未来版本可能定义：

- 非 HTTPS 的 principal 标识符方案，例如 DID method；
- controller key 标签与 principal document 的第三方认证；
- 保护隐私的 controller 绑定，例如盲化或零知识条目；
- 常见应用的标准 scope registry；
- subject 签名的 delegation 接受或拒绝；
- 委托 Profile 管理；
- 跨提供方 delegation 镜像与状态复制；
- JSON Schema 和一致性测试。
